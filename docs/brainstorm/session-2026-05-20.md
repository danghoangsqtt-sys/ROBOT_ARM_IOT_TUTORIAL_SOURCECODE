## 1. Tổng quan Dự án

Xây dựng **~27 file mã nguồn mẫu** (C/C++ firmware + Python GUI + IoT) cho giáo trình thực hành đại học — điều khiển **Cánh tay Robot 6DOF** với ESP32 + PCA9685.

**Đặc thù quan trọng:** Mã nguồn được **in trong sách giáo trình** → sinh viên **tự đánh máy** từ sách → yêu cầu code **cực kỳ rõ ràng, dễ đọc, dễ gõ, có comment giải thích chi tiết**.

### Thông số phần cứng
| Thành phần | Chi tiết |
|---|---|
| MCU | ESP32 DevKit V1 (ESP-WROOM-32S) |
| PWM Driver | PCA9685 — I2C address `0x40`, 50Hz, 12-bit |
| Servo | 6x MG995/MG996 (khung hợp kim nhôm) |
| Nguồn servo | 5V–6V / 3A ngoài |
| I2C pins | SDA = GPIO 21, SCL = GPIO 22 |
| PWM range | SERVOMIN = 102 (0.5ms→0°), SERVOMAX = 512 (2.5ms→180°) |

### Bảng cấu hình 6 khớp Robot
| Khớp | Tên | Chức năng | Min° | Max° | Home° | Kênh PCA |
|------|-----|-----------|------|------|-------|----------|
| J0 | Base (Đế) | Xoay toàn bộ | 0 | 180 | 90 | 0 |
| J1 | Shoulder (Vai) | Nâng/hạ cánh tay trên | 70 | 150 | 70 | 1 |
| J2 | Elbow (Khuỷu) | Gập/duỗi cánh tay dưới | 0 | 150 | 90 | 2 |
| J3 | Wrist Pitch | Ngửa/úp bàn kẹp | 0 | 180 | 90 | 3 |
| J4 | Wrist Roll | Xoay bàn kẹp | 0 | 180 | 90 | 4 |
| J5 | Gripper (Kẹp) | Mở/đóng kẹp | 60 | 120 | 90 | 5 |

## 2. Quyết định Thiết kế (Đã Thống nhất)

> Tất cả quyết định dưới đây được chọn theo tiêu chí: **tối ưu nhất, đẹp nhất, dễ học nhất**.

### QĐ-01: Thư viện Adafruit_PWMServoDriver
- **Quyết định:** Sử dụng **phiên bản mới nhất** (không ghim version cụ thể trong `lib_deps`).
- **Lý do:** PlatformIO tự quản lý dependency, giảm bước cấu hình cho sinh viên. Thư viện Adafruit PWM rất ổn định, backward-compatible giữa các phiên bản.

### QĐ-02: Comment tiếng Việt KHÔNG DẤU — Áp dụng toàn bộ
- **Quyết định:** Áp dụng **thống nhất cho tất cả file** (C/C++ lẫn Python `.py`).
- **Lý do:** Đảm bảo đồng nhất toàn giáo trình khi in sách. Một số nhà in/phần mềm dàn trang có thể không render đúng Unicode trong code block. Tránh nhầm lẫn cho sinh viên khi một nửa comment có dấu, nửa không.

### QĐ-03: Cổng nạp (upload_port)
- **Quyết định:** Đặt `upload_port = COM9` kèm ghi chú rõ ràng ở **dòng kế bên**:
  ```ini
  upload_port = COM9           ; <-- DOI THANH COM PORT THUC TE CUA BAN
  ```
- **Lý do:** Sinh viên nhìn thấy ngay chỗ cần thay đổi khi cắm thiết bị vào cổng USB khác. Ghi chú trực tiếp trên cùng dòng dễ thấy hơn là ghi ở đầu/cuối file.

### QĐ-04: Blynk IoT phiên bản mới (v1.0+)
- **Quyết định:** Sử dụng **Blynk IoT mới** với `BLYNK_TEMPLATE_ID`, `BLYNK_TEMPLATE_NAME`, `BLYNK_AUTH_TOKEN`.
- **Lý do:** Blynk Legacy đã ngừng hỗ trợ. Blynk IoT mới hỗ trợ cả Web Dashboard + Mobile App trên cùng firmware, có tính năng OTA và reconnect tự động — phù hợp nội dung giảng dạy IoT hiện đại.

### QĐ-05: Tốc độ Smooth Move
- **Quyết định:** Giới hạn tốc độ **1–10** (integer), công thức delay: `delayMs = 20 / speed`.
- **Lý do:**
  - Speed=1 → delay 20ms/bước → chậm nhất (~3.6 giây cho 180°) — an toàn cho servo, dễ quan sát.
  - Speed=10 → delay 2ms/bước → nhanh nhất (~0.36 giây cho 180°) — mượt, không giật.
  - Dải 1–10 đơn giản, dễ nhớ, dễ giải thích trong giáo trình.

### QĐ-06: Cấu trúc thư mục đầu ra
- **Quyết định:** Tạo trực tiếp thư mục `robot-arm-source-code/` tại **gốc workspace**.
- **Lý do:** Đúng cấu trúc đề bài yêu cầu, giữ sạch workspace. File prompt gốc `.md` nằm cùng cấp với thư mục output.

### QĐ-07: Naming Convention
- **Quyết định:** Tên biến/hàm dùng **snake_case** nhất quán cho cả C++ và Python.
- **Lý do:** snake_case phổ biến trong embedded C, đồng thời cũng là chuẩn PEP 8 của Python → sinh viên chỉ học 1 quy tắc đặt tên duy nhất cho cả 2 ngôn ngữ.

### QĐ-08: Xử lý lỗi đầu vào
- **Quyết định:** Tất cả lệnh Serial không hợp lệ đều trả về chuỗi `ERR:<mã_lỗi>` — firmware **không bao giờ crash** khi nhận input sai.
- **Mã lỗi chuẩn hóa:**
  - `ERR:INVALID_CMD` — lệnh không nhận dạng được
  - `ERR:INVALID_JOINT` — id khớp ngoài phạm vi 0–5
  - `ERR:MISSING_PARAM` — thiếu tham số
  - `ERR:NEED_6_ANGLES` — lệnh A thiếu đủ 6 góc
- **Lý do:** Giúp sinh viên hiểu defensive programming. Phản hồi lỗi có cấu trúc giúp debug dễ dàng và cũng dễ parse từ Python GUI.

## 4. Kiến trúc Tổng thể Hệ thống

### Sơ đồ Luồng Dữ liệu

```
┌──────────────┐     Serial     ┌──────────────┐     I2C      ┌──────────┐
│   PC/Python  │ ◄────────────► │   ESP32      │ ◄──────────► │ PCA9685  │
│  (GUI/CLI)   │   115200 baud  │ (Firmware)   │  0x40, 50Hz  │  16-CH   │
└──────────────┘                └──────────────┘              └────┬─────┘
                                       │                          │ PWM
                                       │ WiFi                     │ 0–5
                                       ▼                     ┌────┴─────┐
                                ┌──────────────┐             │ 6 Servo  │
                                │ Blynk Cloud  │             │ MG995/96 │
                                │ (Web+Mobile) │             └──────────┘
                                └──────────────┘
```

### Sơ đồ Module Firmware (Bài 4 GD2+)

```
main.cpp
  ├── config.h            (cau hinh 6 khop, hang so)
  ├── pca9685_driver.h/cpp (I2C → PCA9685 → PWM)
  ├── servo_ctrl.h/cpp     (quan ly 6 servo, smooth move)
  └── cmd_parser.h/cpp     (parse lenh Serial → goi servo_ctrl)
```

### Giao thức Serial Command (Protocol)

```
Gửi: <LENH> [tham_so_1] [tham_so_2] ... <LF>
Nhận: <PHAN_HOI><LF>

Bảng lệnh:
  M <j> <a>    →  OK               | Di chuyen khop j den goc a
  G <j>        →  VAL:<j>:<a>      | Doc goc khop j
  T            →  STA:a0,a1,...,a5  | Trang thai tat ca khop
  H [j]        →  OK               | Ve Home (1 khop hoac tat ca)
  I            →  (bang thong tin)  | In cau hinh khop
  S <j> <s>    →  OK               | Dat toc do khop j (1-10)
  A <a0>...<a5>→  OK               | Di chuyen dong thoi 6 khop
  W            →  DONE             | Cho hoan thanh chuyen dong

Lỗi:
  ERR:INVALID_CMD     Lenh khong hop le
  ERR:INVALID_JOINT   ID khop ngoai pham vi 0-5
  ERR:MISSING_PARAM   Thieu tham so
  ERR:NEED_6_ANGLES   Lenh A thieu du 6 goc
```

## 5. Nguyên tắc Sư phạm cho Code

### A. Cấu trúc Comment Header (mỗi file)
```cpp
// =============================================
// BAI THUC HANH 4 - GIAI DOAN 2
// File: config.h
// Mo ta: Khai bao cau hinh 6 khop Robot Arm
// =============================================
```

### B. Comment mỗi hàm
```cpp
// ------------------------------------------
// Ham: servo_move
// Chuc nang: Di chuyen 1 khop den goc dich
//   - Clamp goc trong pham vi [min, max]
//   - Di chuyen muot: 1 do moi buoc
//   - Toc do dieu chinh bang delay
// Tham so:
//   joint: chi so khop (0-5)
//   targetAngle: goc dich (do)
// ------------------------------------------
```

### C. Placeholder đánh dấu rõ
```cpp
char ssid[] = "TEN_WIFI_CUA_BAN";       // <-- THAY BANG TEN WIFI THUC TE
char pass[] = "MAT_KHAU_WIFI";           // <-- THAY BANG MAT KHAU WIFI
#define BLYNK_AUTH_TOKEN "YOUR_TOKEN"     // <-- THAY BANG AUTH TOKEN TU BLYNK
```

### D. Triết lý "Dễ Học Nhất"
1. **Progression rõ ràng:** GD1 → GD2 → GD3 mỗi bài đều tăng dần độ khó, không nhảy vọt.
2. **Code kế thừa:** GD3 kế thừa GD2, chỉ thêm/sửa — không viết lại từ đầu → sinh viên thấy được quá trình phát triển phần mềm thực tế.
3. **Comment = Giáo trình:** Comment chi tiết đến mức sinh viên có thể hiểu logic chỉ bằng đọc comment mà chưa cần hiểu cú pháp.
4. **Mỗi file ≤ 120 dòng:** Phù hợp 2–3 trang sách, không gây overwhelm.
5. **Tên biến tự giải thích:** `currentAngles`, `homeAngle`, `clampAngle`, `moveServo` — đọc tên biết ngay chức năng.
